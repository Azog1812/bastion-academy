# 0013 — Shared environments: a real Wazuh, started and stopped from the web UI

**Status:** accepted (31 Oct 2026)

## Context
The optional Wazuh module (ADR 0012) teaches a real SIEM: decoders, XML rules, alerts.
Reading about it is not enough; a learner must click through a real dashboard. Wazuh
is three heavy containers (indexer, manager, dashboard, about 4 GiB of RAM together),
so it cannot run all the time on a laptop, and it cannot be a per-learner lab either:
one instance per learner would not fit on any machine, and the images are not ours.

Learners asked to start and stop it from the web UI, depending on their machine. The
only component allowed to touch Docker is the lab runner (invariant 15); giving the
platform the socket, or letting the runner create arbitrary containers, would turn a
web bug into root on the host.

## Decision
- **Installed once by the operator, from reviewed configuration.**
  `docker compose --profile wazuh up -d` creates the containers with fixed
  `container_name` values. Two one-shot setup containers run first, with
  `network_mode: none`: `certs.sh` makes a private CA and the TLS certificates with
  openssl (the official generator downloads its tool from the Internet at every run,
  unpinned: code we would execute unseen), and `users.sh` writes the indexer users
  **without the demo accounts** (their passwords are public), hashing the passwords
  generated by `gen-secrets` (24 random characters, about 144 bits). Both are idempotent.
- **The runner may only inspect, start and stop names from the catalog.**
  `src/labs/environments.ts` is the closed set (`wazuh` → three container names, URL,
  maximum run time). The runner's internal API takes an environment id validated with
  `z.enum`, nothing else: no name, image, mount or port ever comes from a request,
  and `EnvironmentController` makes no create call at all.
- **Same gate as lessons and labs.** `GET /v1/environments`, `POST
  /v1/environments/:id/start|stop` answer 403 unless the learner has the module added
  and unlocked (`isModuleUnlocked`, ADR 0012). A locked learner does not even get the
  live state (nothing about the host's containers). Every start and stop, allowed,
  denied or failed, is audited (`environment.start`, `environment.stop`), and both
  routes share the per-account lab rate limiter.
- **Secrets stay on the host.** The UI shows the login *hint* ("user admin, password
  `WAZUH_ADMIN_PASSWORD` from your .env"), never the password. The only link the page
  will render is an `https://localhost:<port>` URL, and only while the stack is running.
- **Contained.** The Wazuh containers talk on their own `internal` network (no route
  out: no feed download, no telemetry); only the dashboard joins a second network to
  publish `127.0.0.1:8443`. Indexer and dashboard drop all capabilities; the manager
  keeps its own (s6 runs as root, then drops to the `wazuh` user) with no-new-privileges.
  Memory is capped per container.
- **Forgotten stacks stop themselves.** The runner's reaper stops an environment
  running longer than `maxRunSeconds` (8 h), measured from the containers' own start
  time, so it survives a runner restart.

## Rejected options
- *Mounting the Docker socket in the platform*: a single SSRF or injection would become
  host root. The runner stays the only socket holder.
- *Letting the runner `compose up` on request*: it would need the compose file, the
  images and create rights, which is exactly what invariant 15 refuses.
- *One Wazuh per learner*: 4 GiB each; a classroom on one server could never run it.
- *The official certificate generator*: it downloads its tool at run time, unpinned.

## Consequences
- The environment is shared: on a multi-learner install, one learner can stop Wazuh
  while another uses it. Acceptable locally (one learner); hosting would need ownership
  or a lease, and a real per-tenant Wazuh.
- Changing a Wazuh password after the first start needs `securityadmin` (runbook).
- Next: challenges graded on Wazuh rules, and a decoder for Bastion's own audit log so
  learners can watch the platform they use.
